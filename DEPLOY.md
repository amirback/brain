# Деплой и домен

Сейчас проект живёт на GitHub Pages: https://amirback.github.io/brain/

Сборка публикуется автоматически при пуше в `main` — workflow в
[.github/workflows/deploy.yml](.github/workflows/deploy.yml) собирает статику и
force-push'ит её в ветку `gh-pages`.

## Переезд на Vercel

Vercel лучше подходит под покупку домена: подключение делается за пару минут,
HTTPS-сертификат выпускается сам, а превью-сборка появляется на каждый пул-реквест.
GitHub Pages при этом можно оставить как запасной адрес — конфликта нет.

### Что нужно сделать

1. Зайти на vercel.com через GitHub и импортировать репозиторий `amirback/brain`.
2. Framework Preset определится сам как Next.js. Build Command и Output Directory
   менять не нужно.
3. **Важно: не задавать переменную `NEXT_PUBLIC_BASE_PATH`.**

Третий пункт — единственная реальная тонкость. GitHub Pages отдаёт сайт из
подпапки `/brain`, поэтому в CI эта переменная выставлена в `/brain`, и все ссылки
и ассеты получают такой префикс. Vercel отдаёт сайт с корня домена, и тот же
префикс сломает вообще все пути. Логика уже написана так, что пустая переменная —
это корректный корневой режим ([next.config.ts](next.config.ts)), поэтому на Vercel
достаточно просто ничего не выставлять.

### Ключ для ИИ-наставника

Чтобы наставник отвечал на свободные вопросы, в Vercel нужно добавить одну
переменную: Settings → Environment Variables →

```
ANTHROPIC_API_KEY = sk-ant-...
```

Ключ берётся в консоли на platform.claude.com. После добавления переменной
нужно сделать **Redeploy** — Vercel не подхватывает новые переменные в уже
собранный деплой.

Без ключа сайт продолжает работать: наставник молча переключается на свою
правиловую версию и отвечает по данным ученика и материалам курса. Ничего не
ломается, просто исчезает свободный диалог.

**Не клади ключ в код и не коммить его.** Он читается только на сервере
([src/app/api/mentor/route.ts](src/app/api/mentor/route.ts)); в браузер он не
попадает никогда.

### Почему статический экспорт стал условным

Раньше в `next.config.ts` всегда стоял `output: "export"`. POST-роут и
статический экспорт несовместимы: экспорт умеет отдавать только готовые файлы.
Теперь экспорт включается переменной `STATIC_EXPORT=1`, которую ставит только
workflow GitHub Pages — он же удаляет папку `src/app/api` перед сборкой.

На Vercel обе переменные не задаются, поэтому собирается серверная версия с
роутом. Ничего вручную настраивать не нужно.

### Домен с Namecheap

После первого успешного деплоя:

1. В проекте на Vercel: Settings → Domains → добавить купленный домен.
2. Vercel покажет, какие записи прописать. Проще всего в Namecheap на вкладке
   Advanced DNS добавить:
   - `A` запись для `@` → IP, который покажет Vercel (сейчас это `76.76.21.21`,
     но сверяйся с тем, что показывает панель, а не с этим файлом);
   - `CNAME` для `www` → `cname.vercel-dns.com`.
3. Дождаться распространения DNS. Обычно 10–30 минут, иногда до нескольких часов.
   Сертификат Vercel выпустит сам, ничего нажимать не нужно.

Альтернатива — переключить в Namecheap нейм-серверы на Vercel целиком
(Domain → Nameservers → Custom DNS). Тогда записями управляет Vercel, и это
надёжнее, если не хочется разбираться с DNS вручную.

### Что поменять после переезда

- В [README.md](README.md) и в питч-деке заменить живую ссылку на новый домен.
- Если GitHub Pages больше не нужен, workflow можно удалить. Если нужен как
  запасной — оставить как есть, он не мешает.

## Локальная сборка и ручная публикация

Если Actions зависнут (такое уже случалось: раннер не выдавался больше часа),
сайт можно выложить руками — это ровно то, что делает workflow:

```bash
NEXT_PUBLIC_BASE_PATH=/brain npm run build
cd out && touch .nojekyll && git init -b gh-pages
git add -A && git commit -m "Deploy"
git push --force git@github.com:amirback/brain.git gh-pages
```
